## What these results mean

**USB2 startup:** EN goes high at 5 ms, so the nominal 4 V crossing occurs
about **7.685 ms after enable**. Sweep crossings are about 4.023–19.589 ms
after enable. The slowest case uses 240 uF, 115 mA limiting and a 100 mA
load envelope. Higher capacitance and less charging-current margin delay
startup. The load tapers below 4 V; real dongle constant-power behavior or
boot bursts can change this substantially. These timings cannot define the
firmware FAULT timeout until a validated TPS2553 model and actual load replace
the abstractions. Current limiting at the programmed value is built into
the model, rather than independent verification of the ILIM resistor choice.

**USB2 overload:** the 250 mA demand exceeds the 115–159 mA programmed
limits and the output collapses. Low-voltage load taper explains its nonzero
equilibrium; that voltage is not a predicted real dongle operating state.
Recovery after demand removal works in this abstraction. Real FAULT deglitch,
thermal shutdown, reverse blocking and firmware response remain untested.

**Shared 5 V:** this is the most actionable sensitivity result. The lowest
rail occurs with a 4.75 V source, 0.6 Ω series resistance and a 378 mA RGB
pulse: **4.403 V**. Peak source current across the sweep reaches **719 mA**;
average current over the measurement window reaches **325 mA**. Modeled
RLC transients can exceed the sum of steady load currents. Average current
alone therefore does not close a provisional 500 mA power budget. These
figures use an assumed 10 uF effective input bank, ideal current load steps
and lumped cable R/L, not extracted board capacitance or measured PWM.
Next priority: obtain actual RGB/host waveforms and source/cable/fuse
impedance, then rerun against reviewed receiving-device voltage limits.

**3.3 V:** the small voltage drop follows the ideal source and imposed
0.1 Ω series resistance. It confirms the load-step fixture executes, but
does not establish TLV73333 startup, dropout, stability, or RP2350 core
converter performance. The steady minima do not establish the required
effective capacitance; add a vendor model and actual rail network first.

**Bypass:** reducing effective capacitance from 100 nF to 50 nF roughly
doubles impedance at 1 MHz. The roughly 50 mΩ minimum is the deliberately
assigned ESR near branch resonance. Neither result is a whole-board PDN
measurement or a USB/RGB ringing/ESD assessment.

## Execution fixes and limits

The initial decks used `ternary(...)`, which this ngspice runtime rejected.
The generator now emits native conditional expressions. Added a zero-volt
Vsense source to measure U7 abstraction current: `i(Bswitch)` was unavailable
as a measurement vector. Both corrections were regenerated into the KiCad
entry sheets and decks before the successful runs.

Added a shared-library worker to the batch runner. Every case runs in a
separate process, with timeout protection and saved waveforms. The runtime
reports missing `spinit`; these simple decks ran with default compatibility
mode at 27 °C, without XSPICE code models. This run did not exercise the
KiCad simulator GUI or validate vendor-model compatibility. Native KiCad CLI
was located but its initial invocation reported sandbox-denied user settings;
no CLI validation result is claimed here.

Simulation did not modify manufacturing PCB/schematic files. Their recorded
LF-normalized hashes still match the scaffold baseline. No physical voltage,
current, thermal, USB, ESD, or firmware test has been completed by these runs.

## Reproduce

```powershell
python spice/run_suite.py --shared-library 'D:/Program Files/bin/ngspice.dll' --output-dir results/2026-10-05/nominal
python spice/run_suite.py --shared-library 'D:/Program Files/bin/ngspice.dll' --sweep --output-dir results/2026-10-05/sweeps
```

Choose a fresh output directory for subsequent runs to preserve this evidence.
The shared-library API is documented in the
[ngspice manual](https://ngspice.sourceforge.io/docs/ngspice-manual.pdf).
